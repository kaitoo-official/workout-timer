# workout-timer（筋トレタイマー）

自分の筋トレメニュー（種目・回数・時間・休憩・周回）を順番に回す iPhone 用タイマーです。アプリ名はまだ決めていません。
**アプリを開かずに、ロック画面と Dynamic Island だけで最後まで進められる**ことを目標に、サーバーを使わずに作っています。

| | |
|---|---|
| 状態 | 開発中。TestFlight の内部テストで実機確認を続けている（ビルド104・2026-10-20） |
| 対象 | iOS 26 以降（SwiftUI）。保存データの形式は Android 版でも同じものを使う前提 |
| 作者 | KAITOO Works（個人開発・自分で使うために企画） |

## 主な機能
- メニューの作成・編集（種目は回数制／時間制、休憩・周回間休憩、周回数）。回数と時間はホイール、周回数は数字キーで入力
- 区間を自動で並べて順番に進行（回数制は「完了」を押すまで待ち、時間制と休憩は時間で自動に進む）
- ロック画面・Dynamic Island の Live Activity に今の区間と残り時間を表示。完了・一時停止・再開・スキップのボタンつき
- 区間の始まりの音（カウントダウン・チャイム）と通知。YouTube を全画面で再生中でも届く
- 中断と復帰：アプリが止まっていた間の進行は、復帰したときに今の時刻までまとめて進める

## 仕組み
```
WorkoutCore（Swift Package・OS に依存しない）
  Menu → Plan（区間の並び） → Session（進行・取り消し・二重操作の防止）
  Schedules（Live Activity と通知の予約計画）／AutoChain（開始前の制限判定）／Store（保存）
        │
app/（SwiftUI）
  SessionController … 画面とロック画面のボタンが同じ進行を共有
  LiveActivityService／NotificationService … 予約計画を ActivityKit・通知に反映
  Widget … ロック画面・Dynamic Island の表示
```
- 進行は**終了予定時刻**で管理する（タイマーが何回動いたかは使わない）。自動で次へ進むときは前の区間の終了予定時刻をそのまま次の開始にするので、遅れが積み重ならない
- 操作には「どの区間を見て押したか」を付ける。押した時点で今の区間が変わっていたら無視する（連打や古い表示からの操作で二重に進まない）

## 開発で対応した主な課題
本体を作る前に、検証版（`probe/`）を iPhone 実機で6回試して、OS の制約を確かめました。

| 課題 | 分かったこと（実機） | 対応 |
|---|---|---|
| アプリが止まっている間に Live Activity の表示を切り替えたい | 任意の時刻に表示を更新する公式の方法はない（自動で変わるのはタイマー表示だけ） | iOS 26 の「指定時刻に Live Activity を開始する予約」を区間ごとに使う |
| 予約した表示が無操作で先へ進まない | 予約は同時5件まで。裏で動けるのは30〜75ミリ秒で、裏からの新しい予約は「Target is not foreground」で拒否される | サーバーなしで無操作で進むのは「最後の操作から4区間先まで」と決め、開始前にメニューを判定する（`AutoChain`）。長すぎるメニューは自動開始オフかメニューの修正を案内 |
| ロック画面に終わった区間の表示が溜まる | 予約の開始時に裏で短く動ける | その間に先に次の区間を予約し、後で古い表示を終了する順番に変更 |
| ロック画面のボタン操作の後、先の区間の予約ができない | ボタンからは今の区間しか開始できない | 操作の後は、区間を行で並べた1つの「まとめ表示」に切り替える → アプリを一度も開かずにロック画面だけで最後まで完走（ビルド6で合格） |
| 音が動画に負けないか | YouTube 再生中も聞こえ、動画の音は小さくなる。消音スイッチ ON では鳴らない | 機械音のカウントダウン＋区間開始のチャイム（実機で聞き比べて選んだ） |
