# 動作ルール（v1）

iOS・Android の両方で同じに振る舞うための決まりです。
実装：`Packages/WorkoutCore`（画面やOSに依存しない部分）

## 1. 区間の並べ方（メニュー → 区間）
- 周 1〜N について、種目を上から順に並べる。
- 各種目の後に休憩を1つ置く。
  - 周の最後の種目の後：周回間休憩
  - それ以外：その種目の `restAfterOverride`。無ければ種目間休憩
- **最後の周の最後の種目の後は休憩を置かず、そこで終了**。
- 0秒の休憩は区間にしない。

例：CHEST（3種目・3周、種目間60秒、周回間90秒）
`ノーマル15回 → 休憩60 → デクライン15回 → 休憩60 → ナロー15回 → 周回間休憩90 → ノーマル15回 → … → ナロー15回（終了）`

## 2. 区間の始まり方と終わり方
| 区間 | 始まり方 | 終わり方 |
|---|---|---|
| 休憩・周回間休憩 | 前の区間が終わったら自動 | 時間で自動 |
| 時間制の種目（自動開始オン） | 自動 | 時間で自動 |
| 時間制の種目（自動開始オフ） | **開始操作を待つ** | 時間で自動 |
| 回数制の種目 | 自動で表示 | **完了操作を待つ（勝手に完了しない）** |

## 3. 時間の求め方
- 進行は**終了予定時刻**で管理する。画面のタイマーが何回動いたかは使わない。
- 自動で次の区間に進むときは、前の区間の終了予定時刻をそのまま次の開始時刻にする（遅れが積み重ならない）。
- アプリが止まっていた間の進行は、復帰時に「今の時刻」までまとめて進める。

## 4. 操作
| 操作 | できる区間 | 結果 | 取消の対象 |
|---|---|---|---|
| 完了 | 回数制（完了待ち） | 完了数+1、次の区間へ | ○ |
| 開始 | 時間制（開始待ち） | 計測開始 | ○ |
| 一時停止 | 時間制・休憩（計測中） | 残り時間を保存して停止 | — |
| 再開 | 停止中 | 残り時間から再開 | — |
| 休憩延長（+30秒など） | 休憩（計測中・停止中） | 終了予定を延ばす | ○ |
| スキップ | 全区間 | 次の区間へ。**種目のスキップは完了数に含めない** | ○ |
| 次へ（まとめ表示のボタン） | 全区間 | 完了待ちなら完了、それ以外はスキップ | ○ |
| 取消 | — | 直前の取消対象の操作を1つ戻す（最大20回まで遡れる） | — |
| 途中終了 | — | 確認のうえ終了 | — |

- 取消で戻したときの残り時間は、操作した時点の残り時間を「今」から数え直す。
- 一時停止・再開は、もう一度押せば戻るので取消の対象にしない。
- 時間で自動に進んだ区間は取消の対象にしない（取消は人の操作だけを戻す）。

## 5. 二重操作の防止
- 操作には「どの区間を見て押したか」を付ける。アプリ画面は区間番号を、まとめ表示は表示中の区間の範囲を付ける。
- 押した時点で、今の区間がその範囲から外れていたら、その操作は無視する（連打・古い表示からの操作で二重に進まない）。
- 操作の前に必ず「今の時刻まで進める」処理をしてから判定する。

## 6. 自動で進む連続区間と、開始前の制限判定
**自動で進む連続区間**とは、人の操作で始まった区間から、次に人の操作が要る区間（回数制の種目／自動開始オフの時間制の種目）までの並びです。その区間を含み、休憩と周回間休憩も数えます。

ロック画面で操作した後は、この並びを1つの「まとめ表示」で出します。まとめ表示は**最大4行**です（実機で確認できた予約数を元にした安全側の固定値）。そのため、メニューの中で一番長い連続区間が4行を超える場合は、**自動進行のまま開始できない**ようにします。

判定は、すべての区間について「そこから始まった場合の連続区間の長さ」を数え、最大値で行います（スキップ・再開で途中から始まる場合も含む）。

| 例 | 一番長い連続区間 | 行数 | 判定 |
|---|---|---|---|
| CHEST（回数制のみ・3周） | 休憩 → デクライン15回 ／ 周回間休憩 → ノーマル15回 | 2 | 開始できる |
| 時間制まじり（自動開始オン） | 休憩 → プランク30秒 → 休憩 → 腕立て15回 | 4 | 開始できる |
| 時間制が続く（自動開始オン） | 休憩 → プランク → 休憩 → サイドプランク右 → 休憩 → サイドプランク左 → 休憩 → ロシアンツイスト | 8 | **開始できない** |

開始できない場合は、どこが長いかを示し、次のどちらかを選んでもらいます。
- 自動開始をオフにして始める（時間制は開始ボタンで始まる。連続区間は最長でも「時間制 → 休憩 → 次の種目」の3行）
- メニューを直す

## 7. ロック画面・Dynamic Island の表示
| 状況 | 表示 |
|---|---|
| アプリが前面にある | 今の区間を即時表示し、連続区間の後続（最大3つ）を開始時刻つきで予約する。区間ごとに見出しが切り替わる |
| 予約した区間が始まった | 裏で、終わった区間の表示を消す |
| ロック画面・Dynamic Island で操作した | 先の予約はできない（OSが拒否）ため、連続区間を行で並べた「まとめ表示」を1つ出す。見出しは「進行予定」と周回（古くなる種目名は見出しにしない） |
| 一時停止中 | 今の区間だけを、止まった残り時間つきで表示 |
| 終了 | 表示をすべて閉じる |

- 予約が一部しか成功しなかった場合（端末やOSの上限が想定より少ない等）は、予約した分を閉じてまとめ表示に切り替える。表示・通知・保存状態は常に同じ進行状態から作り直す。

## 8. 通知と音
- 連続区間の各境界について、**5秒前（予告音）**と**開始時（チャイム）**の通知を予約する。メニューの最後が時間で終わる場合は、終了時に**終了音**の通知を予約する。
- 操作のたびに、このアプリの予約通知・表示済み通知をすべて消してから組み直す。一時停止中は予約しない。
- 予告音・開始音・終了音・アプリ内の触覚は、それぞれオン／オフできる。
- 音は iPhone の消音スイッチ・集中モード・通知設定に従う。アプリから通知の音量や振動を強制することはできない。

## 9. 保存と復帰
- メニュー、設定、進行中のセッションを端末内に保存する。操作のたびにセッションを保存する。
- セッションには、開始時点のメニューの写しを持たせる。進行中にメニューを編集しても崩れない。

| 状況 | 保証する範囲 |
|---|---|
| 普通にホーム画面へ戻る・ロックする | 予約済みの表示・通知で進行する。復帰時に今の時刻まで進めて表示を合わせる |
| アプリスイッチャーで強制終了 | 予約済みの通知と表示はOSに残る。ロック画面のボタンを押すとアプリが裏で起動し、保存した状態から続ける。次にアプリを開いたときに今の時刻まで進める |
| 端末の再起動 | 表示は消える可能性がある。次にアプリを開いたときに、保存した状態から今の時刻まで進めて続ける |

（強制終了・再起動の欄は設計上の想定。実機での確認は3週目に行い、結果でこの表を更新する）

## 10. メニュー編集の数値入力（iOS ビルド104〜。Android も同じ操作にする）
| 項目 | 入力方法 | 範囲 | 刻み |
|---|---|---|---|
| 周回数 | 数字をタップしてテンキー入力＋ −／＋ | 1〜20周 | 1 |
| 回数制の種目 | 値をタップ → 下から1列ホイール | 1〜999回 | 1回 |
| 時間制の種目 | 値をタップ → 下から2列ホイール（分／秒） | 0分01秒〜60分00秒（**0秒は決定できない**） | 分1・秒1（秒は00〜59の2桁） |
| 休憩（種目の間・周回の間・種目ごと） | 時間制と同じ2列ホイール | 0分00秒〜30分00秒（**0は「なし」＝休憩をはさまない**） | 分1・秒1 |

- ホイールは「決定」を押したときだけ値を書き戻す。「キャンセル」・下へのスワイプで閉じた場合は元の値のまま。
- 一番上の分（時間制60分・休憩30分）を選ぶと、秒は00だけになる。
- 保存形式は今までどおり**整数の秒**（例：1分30秒 → 90）。分・秒への変換は表示と入力のときだけ行う（`WorkoutCore/Duration.swift`）。
- テンキー入力（周回）は、範囲外を入れると範囲内に丸め、空欄のまま閉じると元の値に戻る。
